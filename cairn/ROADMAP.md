- Self-contained native checks: in a self-contained page the native `<object>` gets a `blob:` PDF, but only its bytes are checked (fetch in Chromium). Its display in desktop Safari and Firefox, `#page=` on a `blob:` URL, and the file name that the native viewer's own save button uses are not checked (M002 review) — added 2026-10-18 — started M020
- Make Safari native embeds honor page: desktop Safari 27.0.1 opened a native `<object>` of `sample.pdf#page=2` at page 1, for the file address and a `blob:` copy alike, while README's `page` option promises the initial page; Chromium 155 and Firefox 158 opened page 2 (M020 plan probe) — added 2026-10-19

The README version badge shows the latest release, 0.5.0, while the extension is at 1.2.6, and v1.1.0 to v1.2.6 have no tags, so these releases alone do not make the badge current (corrected 2026-10-19) — added 2026-10-18 — DESIGN Known issues
- Safari names on iOS: on iPhone and iPad, Safari's names are not checked: ios_check reads only the page DOM (embed name, hidden text, indicator text), and not the toolbar controls. On 2026-10-19 `tests/safari_check.mjs --target simulator` got "Could not find any session hosts that match the requested capabilities" from safaridriver on the iOS 27.0 simulators, whose Safari "Remote Automation" setting was not turned on, and `--target page-script` found no `Element.prototype.computedName`. Turning that setting on is the next try (M010 implement) — added 2026-10-19
- [low] First-paint robustness: find load cases where an on-screen page still does not render after the v1.0.1 and v1.0.2 fixes. Since M001, `auto` puts iPhone and iPad on this timer path, and `ios_check.mjs` scrolls before it measures, so a no-scroll first paint on iOS is untested (M001 review) — added 2026-10-18 — DESIGN Known issues
- [low] Apple touch detection edge cases: `isAppleMobile()` treats any Macintosh user agent with `maxTouchPoints > 1` as an iPad, which may also catch Safari on visionOS or a Mac with a third-party touch driver; not verified (M001 review) — added 2026-10-18
- [low] Run the render checks in Firefox: desktop Firefox is a promised desktop browser, but only M020's `native_check.mjs` runs in it; the render_check, name, text, and remote lines run in Chromium and Safari only. Firefox 158 is installed and starts under puppeteer-core once one `open -g -a Firefox` launch has made its folder (M020 plan) — added 2026-10-19
- [low] Embed name follow-ups: see "Safari names on iOS". `fileName()` gives "." for `./`, ".." for `../`, "a/b.pdf" for `a%2Fb.pdf`, the whole address for `about:blank`, and a trailing space for `sample.pdf%20`; a self-contained embed whose download link has a query and no `.pdf` value now downloads as "document.pdf", not its last path segment; ios_check accepts any "Page i of n", so an indicator that never updates on scroll passes in Safari; `fileName()` also gives the whole address for `https:\\ex.com\a.pdf` (browsers read `\` as `/`), none for `get?a.pdf` and `view?file=https://o.com/x.pdf?y=1`, "report?x=a.pdf" for `report%3Fx=a.pdf`, and itself for `javascript:void(0)`; a query-style embed downloads by the server's name ("get"), not by the name rule; render_check and safari_check read whether page 1 moved before a 300 ms wait in which page heights can change (a false failure only, for mixed page sizes); safari_check calls `process.exit` right after `console.log`; no check covers AC2's counting of a failed embed in n (a page with one loaded and one failed embed of the same file), and ios_check does not check that a failed embed has no name; render_check and safari_check treat a frame of zero size as scrolled past the middle line (a false failure only); a `data-src` that starts with U+00A0 now goes to the inlined path, so on a `file://` page (where the fetch fails) it shows the failure message with no link, where it used to show it with an "Open the PDF" link (not checked in a browser; corrected M011); a broken UTF-8 escape is kept as written in a path segment but becomes U+FFFD in a query value; ios_check and render_check exit 1, not 2, when the browser or the simulator cannot start (M010 review) — added 2026-10-19
- [low] Inlined failure check gaps: see "Remote failure line count" and "Text check follow-ups". The `--expect-download` checks in `render_check.mjs` and `ios_check.mjs` do not check why a decoded inlined PDF failed (any error passes, so a broken PDF.js import on self-contained pages passes `selfcontained_failed_test.html`); the "failed to render an inlined PDF" count is page-wide and the line names no embed; no plant moves an embed between decoded (no `data-src`) and not decoded; render_check reads the link's attributes and clicks the link in two separate reads, waits a fixed 500 ms for a second saved file, and its dlnoname and dlhref plants navigate the page, so the reported reason can be a crash; the "document.pdf" download name of a failed inlined embed with no fallback link is not checked (M011 review) — added 2026-10-19
- [low] Decode failure button link: on a self-contained page, when an embed's inlined `data:` PDF cannot be decoded, the `button` link below the embed still names the separate PDF file, which the page does not ship (M011 plan). The embed itself now shows the message with no link, so IP2's usable fallback is not met there (DESIGN Known issues); whether to record that as a D-entry annotating IP2, as D-003 does for the no-JS link, is the user's decision (M011 review) — added 2026-10-19
- [low] Native name check gaps: see "Name plant slide target" and "Embed name follow-ups". The `fileName()` gaps listed in "Embed name follow-ups" now reach native `<object>` names too, and no test page has a native embed named "PDF" alone or by a query value; render_check's `nativename`, `nativetitle`, and `nativedesc` plants take the page's first native embed, as "Name plant slide target" says of the PDF.js plants; render_check and safari_check leave failed embeds out of the names they expect while the viewer counts them in n, so a page that mixes failed and loaded embeds fails falsely under `--expect-name` (no check line has such a page) (M012 review) — added 2026-10-19
- [low] Shared remote check gaps: see "Remote failure line count". With `--remote cors`, render_check and ios_check count every 206 answer with an Origin header on the PDF's path, so a native viewer that sent an Origin header with range requests would count for the PDF.js embed (the 2026-10-19 logs show none in Chromium or the iOS 27.0 simulators); the native-load check in ios_check and safari_check passes when one GET with no Origin header reached the PDF's path, so on example.html one loaded native embed stands for every native embed of that address; render_check has no native-load check; the viewer's added query covers native embeds on the same page only, not an author's own `<iframe>`, `<object>`, or `<embed>` of the same remote PDF, or a native load earlier in the tab (not checked in Safari) (M014 review) — added 2026-10-19
- [low] LaTeX path escapes: In PDF output M015 decodes only the `%XX` escapes of printable ASCII other than `\ { } # $ & ~ ^ _ " ,`, so a path with an escape for a non-ASCII byte (`%C3%A9`) or for one of those characters keeps the escape and names a file that is not on disk. Those characters given bare in a `\includepdf` path are not handled: an M015 probe found that `"` and `,` fail in lualatex and pdflatex, and that `"`, `)`, and `,` fail in xelatex, and the others were not checked. M015 still decodes `%29` to `)`, which Quarto's default lualatex reads, so a `%29` path fails in xelatex (M015 plan; corrected M015) — added 2026-10-19
- [low] Percent path follow-ups: see "LaTeX path escapes". Whether to record the PDF-output stop for a file LaTeX cannot find (DESIGN Known issues) as a D-entry annotating IP2 is the user's decision. Links in docx, epub, and other formats now carry `%25` for a bare `%`, and no check opens such a link in Word or an e-reader. No `--remote` check runs a page whose `data-src` holds `%25`. A leading `%20` decodes to a leading space in the `\includepdf` path, not probed (M015 review) — added 2026-10-19
- [low] LaTeX inline shortcode: in LaTeX output the shortcode returns a `RawBlock` in inline context. The catcode group that M015 adds for a `%` path works only where TeX has not read the line yet, so an `\includepdf` inside a macro argument such as a footnote is not covered, and no test calls LaTeX output in inline context (M015 review) — added 2026-10-19
- [parked] Self-contained no-JS link: with JavaScript disabled, the fallback link and the `button` link in a self-contained page point at the separate PDF file, which is not shipped, because Quarto inlines `data-src` but not `<a href>`. In Quarto 1.10.19 a shortcode sees no `embed-resources` setting in its metadata or `PANDOC_WRITER_OPTIONS`, so the shortcode cannot tell such a page apart (M002 plan; M005 plan probe) — added 2026-10-18
- [parked] Eager text cost: see "First-paint robustness". Reading every page's hidden text at load keeps each PDF.js page object and its worker fonts (no `page.cleanup()`), and a page render can wait behind one text read. Memory and first-paint delay were not measured on a constrained phone or with a long PDF. The plan's alternative was text only for rendered pages; a measured memory failure or first-paint delay is the evidence for it (M004 review) — added 2026-10-18
- [parked] Screen-reader text gaps: browser find-in-page may match the hidden page text (not checked). Hidden text joins PDF.js items with no added space, but PDF.js 6.1.200 adds space items itself for gaps: an M005 plan probe in Chromium read positioned words, two columns, and a `TJ` gap with spaces, and only a 2 pt gap at 12 pt and a text rise joined with none. A real PDF whose hidden text runs words together is the evidence for a fix (M004 review; narrowed 2026-10-18 by M005) — added 2026-10-18
- [parked] Shared query fallback: see "Shared remote check gaps". The viewer adds `embedpdf=pdfjs` to a PDF.js address that a native embed on the page also loads, in every browser (D-005). The alternatives were a Safari-only rule or a whole-file fetch for that case. A report of a real site that rejects or mis-answers the added query (a signed address, a server that refuses unknown queries) is the evidence for one of them (M014 review) — added 2026-10-19
