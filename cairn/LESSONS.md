# Lessons

Durable repo lessons — build quirks, testing tricks, gotchas worth
remembering next time — captured at milestone end and surfaced at plan time.
Not status, not decisions: a lesson is a reusable "how this repo actually
behaves" note. Cross-cutting *choices* still go to `DECISIONS.md`.

One line per lesson: `- YYYY-MM-DD (M<NNN>): <lesson>`. Two caps: 50 lines
and 20,000 bytes; over either, retire or prune before adding. Corrected in
place when proven false (never append a correction).

- 2026-10-18 (M001): `xcodebuild -downloadPlatform iOS` with Xcode 27.1 installs two runtimes: iOS 27.1 supports only the "iPhone Duo" device type, and the standard iPhones and every iPad need the iOS 27.0 runtime. Check `xcrun simctl list runtimes -j` (supportedDeviceTypes) before `simctl create`.
- 2026-10-18 (M002): With `embed-resources: true`, Quarto 1.10 inlines module scripts as `data:` URLs (its tabsets scripts too), a script of unknown type as its text, and each `data-src` as a `data:` URL, and adds `role="img"` to elements whose `data-src` it inlined. It leaves `<a href>` targets at the file.
- 2026-10-18 (M003): Safari reports a CORS-blocked PDF.js fetch only as "UnknownErrorException: Load failed" (a CORS block and a module-import failure differ only in the message), and a 404 as "ResponseException: Unexpected server response (404)" (corrected M007), while Chromium logs UnknownErrorException for a CORS block and ResponseException for a 404. A check of a failure's cause reads the viewer's own "embedpdf: failed to render <data-src>" line, not any console CORS line: render_check's native `<object>` fetch logs CORS errors of its own. The viewer names the PDF by its `data-src` as written (`sample.pdf`, not the absolute URL) and logs one line per failed embed, so embeds sharing a PDF give as many lines.
- 2026-10-18 (M004): Puppeteer's `page.accessibility.snapshot({ root })` with the default `interestingOnly: true` returns a labeled group's child text node, not the group, so a role or name check needs `interestingOnly: false`. In Chromium a `<canvas>` without `aria-hidden` shows in that tree as role `none`.
- 2026-10-18 (M004): Quarto's self-contained render passes the inlined viewer through esbuild, which drops comments, so a comment-only change to `embedpdf-viewer.js` changes the docs/ library copies but not the self-contained pages.
- 2026-10-18 (M005): Chromium exposes a `title` equal to an element's `aria-label` as its accessible description too (puppeteer snapshot `description`), so the name is read twice. A control named by `title` alone, with its glyph in an `aria-hidden` span, gets that name and no description.
- 2026-10-18 (M005): PDF.js 6.1.200 `getTextContent()` adds `" "` items for gaps between pieces of text and sets `hasEOL` at line changes, so joining `item.str` values already spaces positioned words and columns. A spacing fix needs a PDF that shows the defect first. The vendored browser build does not run in Node, so probe it in Chromium with puppeteer.
- 2026-10-18 (M006): On macOS a Node server listening on 127.0.0.1:N starts with no error while another process listens on `0.0.0.0:N` or `[::]:N` (SO_REUSEADDR), so an EADDRINUSE check sees only a holder on 127.0.0.1 itself. PDF.js 6.1.200 asks for byte ranges only when Content-Length is above 2 × 65536 bytes and the server sends `Accept-Ranges: bytes` (`validateRangeRequestCapabilities` in `pdfjs/pdf.min.mjs`).
- 2026-10-18 (M002): A PDF.js embed on a RevealJS slide that is not shown renders nothing (its pages have width 0), so a render check must go to each slide with `Reveal.slide()` before it measures ink; scrolling the window does not move slides.
- 2026-10-19 (M009): In Chromium's accessibility tree (puppeteer snapshot, `interestingOnly: false`), text with `opacity: 0` stays readable, while `content-visibility: hidden` on the element or an ancestor and `inert` on the element or an ancestor remove it. An inert ancestor leaves the element's own `inert` property false, so a check reads `closest("[inert]")` or walks the ancestors.
- 2026-10-18 (M008): Quarto 1.10 copies a resource and inlines a PDF whose path holds a bare `%` (`files/100%.pdf`), with a "WARN: Invalid URI" line, and keeps the `<a download>` href as written; GitHub Pages and `serveDocs` answer HTTP 400 to a bare `%` path, so the shortcode writes a bare `%` as `%25` since v1.2.6 (corrected M015). A `div.embedpdf` with no `data-src` never hydrates, which makes a quick probe of a check's hydration timeout.
- 2026-10-19 (M010): safaridriver (Safari 27.0.1) refuses a session until "Allow remote automation" is on (Safari Settings > Developer, or `safaridriver --enable` with an admin password). Its "Get Computed Label" returns "" for a plain `span`, so a check reads text by giving the element a name-from-content role such as `heading` for the read. In the iOS 27.0 simulators a `safari:useSimulator` session fails with "Could not find any session hosts that match the requested capabilities", and Safari has no `Element.prototype.computedName`. The simulators' Safari has no Remote Automation switch, and turning on the `com.apple.webinspectord` keys, a reboot, and Xcode 27.1's DeviceHub window did not help. Each booted simulator's Web Inspector socket (`xcrun simctl getenv <udid> RWI_LISTEN_SOCKET`) does work with no setup, and `DOM.getAccessibilityPropertiesForNode` gives Safari's names, a plain `span` again with an empty label (`tests/webinspector.mjs`; corrected M024).
- 2026-10-19 (M011): `fetch()` of a `data:` URL whose base64 holds a character outside the alphabet (`data:application/pdf;base64,@@@@`) rejects in Chromium 155 ("TypeError: Failed to fetch"), desktop Safari 27.0.1, and iOS 27.0 Safari ("TypeError: Load failed"), and a self-contained Quarto 1.10 render keeps such a hand-written `data-src` as written, so it makes a decode-failure fixture. In puppeteer, `browser.target().createCDPSession()` then `Browser.setDownloadBehavior` with `behavior: "allow"` saves a clicked `blob:` link with a `download` name under that name, on `file://` pages too.
- 2026-10-19 (M011): puppeteer-core imported from a script outside the repo fails with ERR_MODULE_NOT_FOUND (ESM ignores NODE_PATH); run a one-off probe from the repo root as `node --input-type=module -e "$(cat probe.mjs)"`.
- 2026-10-19 (M012): Chromium 155 gives an `<object type="application/pdf">` with an `aria-label` the tree role PluginObject and that name, and shows an `aria-description` equal to it as a description; Safari 27.0.1's WebDriver "Get Computed Label" returns that `aria-label` (computed role group). Desktop Safari has no headless mode, so each safaridriver session brings a Safari window to the front; batch `safari_check.mjs` runs.
- 2026-10-19 (M013): On a local server PDF.js 6.1.200 often streams the whole PDF before it asks for any byte range (a 171 KB PDF in 2 of 3 Chromium runs, a 978 KB PDF in 3 of 3), so a range check must send the whole-file answer slowly. Slow only `.pdf` files: Bootstrap's CSS and `pdf.min.mjs` are over 131,072 bytes too, and slowing them stalls puppeteer's `networkidle0` past 30 s.
- 2026-10-19 (M013): `--expect-text` in render_check and ios_check needs one phrase per page that no other page holds, so a PDF built from repeated copies of `sample.pdf` cannot take it.
- 2026-10-19 (M010): The first `xcrun simctl openurl` on a simulator that ios_check just booted can fail with "Operation timed out" (NSPOSIXErrorDomain code 60); the same run passes when repeated.
- 2026-10-19 (M014): A server can tell a native viewer's PDF read from PDF.js's cross-origin read by the Origin header: Chromium 155 and Safari 27 (desktop and iOS 27.0) sent none for an `<object>` read and one for PDF.js's fetch. render_check's own `fetch(o.data)` of a native embed's PDF sends one too, but asks for the whole file. Google Chrome is not installed on this machine; render_check runs with `CHROME_PATH=/Applications/Chromium.app/Contents/MacOS/Chromium`.
- 2026-10-19 (M015): `%` starts a LaTeX comment, so a `%` in an `\includepdf` path needs `\begingroup\catcode`\%=12\relax … \endgroup` on the same line; `\csname @percentchar\endcsname` joins a following letter into one command name. In an `\includepdf` file name, `"` and `,` fail in lualatex, pdflatex, and xelatex, and `)` fails in xelatex only. `quarto render <page>.qmd --to pdf --output-dir <dir outside the project>` leaves no file in the repo, so it can check PDF output without touching `docs/`.
- 2026-10-19 (M016): Quarto's RevealJS 5 in the iOS 27.0 iPhone simulator uses its scrolled view (`Reveal.isScrollView()` true; the iPad does not), where the current slide follows the scroll position and `Reveal.slide()` to the last slide left the slide before it current; scrolling the slide's content into view made it current. `Reveal.getSlides()` selects `.slides section:not(.stack):not([data-visibility="uncounted"])`, so a walk over it skips uncounted slides. A check of which slide is shown reads `Reveal.getCurrentSlide()`, not the slide it asked for.
- 2026-10-19 (M014): To compare the v1.2.4 viewer on one page without a re-render, copy `git show main:_extensions/embedpdf/embedpdf-viewer.js` over that page's `docs/<page>_files/libs/quarto-contrib/embedpdf-<version>/embedpdf-viewer.js`, run the check, and copy the new file back (the server sends `no-store`). In zsh a flag list in a variable needs `${=var}` to split into words.
- 2026-10-19 (M017): In Chromium 155 with puppeteer-core, `new Function` and `eval` inside `page.evaluate`, and a script element added during an evaluate, run under a Content-Security-Policy whose script-src omits `'unsafe-eval'`; only the page's own load-time scripts get EvalError. So such a header cannot show that a check avoids eval. A self-contained Quarto page needs `data:` in script-src, since it holds its scripts as `data:` URLs.
- 2026-10-19 (M018): `docs/native.html` holds no embedpdf embed and no embedpdf link, so `ios_check.mjs --page native.html --expect-embeds 0` makes a quick probe of a plant's "found nothing to plant in" exit. On the iOS 27.0 simulators the three-slide `revealjs_test.html` took 14 s to 18 s per ios_check run, under the 180 s report timeout.
- 2026-10-19 (M017): `page.emulateCPUThrottling` on the large_test.html iphone line: at rates 4 to 40 the old 300 ms-per-page and 4 s waits still found every canvas; at 70 they left pages with no canvas when `--expect-name` was not given (its waits add time); at 100 the page load passed 120 s.
- 2026-10-19 (M019): LuaLaTeX embeds each font subset once per PDF, so 14 pages of text rendered in one run came to 25,999 bytes (61,357 uncompressed); rendering each page in its own run and joining them with `pdfunite` repeats the fonts per page (about 9.5 KB each) and gave 142,962 bytes. `quarto render <file>.md --output-dir <dir>` refuses a file outside the project's render list ("can only be used when rendering projects"); `quarto pandoc <file>.md --pdf-engine=lualatex -o <out>.pdf` builds it.
- 2026-10-20 (M020): Firefox 158 (Homebrew) started from Claude Code, by puppeteer-core or directly, failed with "Could not find profile folder": making `~/Library/Application Support/Firefox` got "Operation not permitted" even outside the sandbox, and a scratch `HOME` did not help. One launch through macOS `open` (`open -g -n -a Firefox --args -headless -screenshot <png> <url>`) made the folder, and puppeteer-core then started Firefox.
- 2026-10-20 (M020): An element screenshot of a native `<object>` PDF shows the browser's viewer in headless Chromium 155 and Firefox 158 (puppeteer-core) and in desktop Safari 27.0.1 (safaridriver). Safari 27.0.1 opens such an `<object>` at page 1 whatever `#page=` says, for a file address and a `blob:` alike. Firefox's viewer reopens a PDF at the page last shown in that profile unless `pdfjs.viewOnLoad` is 1. Two equal screenshots 500 ms apart can still be the viewer before it drew the PDF.
- 2026-10-20 (M020): Screenshots of one PDF in two native `<object>`s differ by position alone: desktop Safari drew the page 1 device pixel apart, and Firefox at scale 1 drew text edges at a fractional position differently (2% to 4% of single pixels). Placing the reference at the embed's fractional position and comparing 4 x 4 block averages at the best shift of up to 2 pixels brought matching pairs to at most 0.0035 of blocks.
- 2026-10-20 (M021): Desktop Safari 27.0.1 opens an `<iframe>` of a PDF at its `#page=` page, where `<object>` and `<embed>` open page 1. An `<iframe>` follows the server's answer: a PDF sent as `application/octet-stream` or with `Content-Disposition: attachment` shows nothing in it and downloads (Firefox 158, Safari 27.0.1), where `<object type="application/pdf">` shows it. A probe or check of such an answer in Safari through safaridriver saves the file in the user's `~/Downloads`, so run those in headless Chromium. A cross-origin fetch cannot read `Content-Disposition` (not CORS-safelisted), so a missing and a hidden header look alike.
- 2026-10-20 (M022): Quarto's RevealJS 5 deck (1050 x 700, margin 0.1, `viewDistance` 3) gives a slide `display:none` when it is 3 or more slides from the current one, so an embed there has no box at load. A native PDF `<iframe>` that loaded with no box opened at page 1 in Chromium 155 and shrunk in desktop Safari 27.0.1 once shown (Firefox 158 was fine). Reveal's scale is the window size x 0.9 / the deck size (the smaller ratio), so no whole-pixel window gives exactly 1; `Reveal.configure({ minScale: 1, maxScale: 1 })` does.
- 2026-10-20 (M022): In puppeteer-core with headless Chromium 155, each native PDF viewer is a target of type "other" at `chrome-extension://mhjfbmdgcfjbbpaeojofohoefgiehjai/index.html`. Its save button is `#save` in `pdf-viewer` > `viewer-toolbar` > `viewer-download-controls` shadow roots, reachable with `Runtime.evaluate` on that target. CDP `Browser.setDownloadBehavior` with `eventsEnabled: true` then reports `Browser.downloadWillBegin` with the `suggestedFilename`.
- 2026-10-20 (M023): Desktop Safari 27.0.1's PDF control bar (zoom out, zoom in, open in Preview, download) shows only while the pointer is over the embed, sits at a height that depends on the embed's size, is missing from WebDriver element screenshots (window screenshots show it), and fades once the pointer stops. With the screen locked (`lsappinfo front` names loginwindow) no bar shows. After a burst of saves (about two runs of three within a few minutes, sooner after a save from another origin) Safari saved nothing for 2 to 3 minutes, with no error the page can see.
- 2026-10-20 (M023): Firefox 158's built-in PDF viewer in an `<object>` or `<iframe>` saved no file under puppeteer-core (download button, menu item, Cmd+S; BiDi download folder or prefs; headless or windowed), while an `<a download>` to the same `blob:` saved at once. Its frames are reachable with `page.frames()`, and `PDFViewerApplication._docFilename` there gives the name it would save: `document.pdf` for a plain `blob:`, the file name for a `blob:` of a `File`. Chromium 155's viewer names a save by the address's last path segment (fragment and `File` name ignored), and `download.pdf` for `data:`.
- 2026-10-20 (M025): A full run of the CLAUDE.md check lines with their prose variants (138 lines) took 28 to 35 minutes. Its desktop Safari lines take over Safari (automation windows in front, the pointer moves for the save check), and a screen that locked mid-run made the Safari save line save nothing. The user objected to Safari runs while their own Safari windows were open, and safaridriver then failed with "session timed out while connecting to a Safari instance". Ask before running the desktop Safari lines. Firefox 158's viewer saves a `blob:` of a `File` under the `File`'s name (hand saves) and reports it as `_docFilename`.
- 2026-10-20 (M024): Over an iOS 27.0 simulator's Web Inspector socket, Safari's page answers only through `Target.sendMessageToTarget` to the page target that `Target.targetCreated` names after `_rpc_forwardSocketSetup:`. A page opened with `simctl openurl` is listed before it loads, and `Runtime.evaluate` does not wait, so a check waits for `document.readyState` "complete" before it counts embeds. Xcode 27.1 ships no Simulator.app; its simulator window is `Contents/Applications/DeviceHub.app`.
- 2026-10-20 (M026): Quarto 1.10.19's `quarto add jmgirard/embedpdf` downloads `archive/refs/heads/main`, not the latest GitHub release (`githubLatestUrlProvider` in `quarto.js`), so a tag or release changes only the releases page and the README badge. `gh api .../releases/tags/<tag> --jq .body` prints the body plus one newline, so a byte compare with its notes file adds one.
