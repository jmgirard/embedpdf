# Lessons

Durable repo lessons — build quirks, testing tricks, gotchas worth
remembering next time — captured at milestone end and surfaced at plan time.
Not status, not decisions: a lesson is a reusable "how this repo actually
behaves" note. Cross-cutting *choices* still go to `DECISIONS.md`.

One line per lesson: `- YYYY-MM-DD (M<NNN>): <lesson>`. Two caps: 50 lines
and 20,000 bytes; over either, retire or prune before adding. Corrected in
place when proven false (never append a correction).

- 2026-10-19 (M009): In Chromium's accessibility tree (puppeteer snapshot, `interestingOnly: false`), text with `opacity: 0` stays readable, while `content-visibility: hidden` on the element or an ancestor and `inert` on the element or an ancestor remove it. An inert ancestor leaves the element's own `inert` property false, so a check reads `closest("[inert]")` or walks the ancestors.
- 2026-10-19 (M010): safaridriver (Safari 27.0.1) needs "Allow remote automation" on, and its "Get Computed Label" returns "" for a plain `span`, so a check gives the element a role such as `heading` for the read. In the iOS 27.0 simulators a `safari:useSimulator` session fails whatever is set, and Safari has no `Element.prototype.computedName`; each simulator's Web Inspector socket works with no setup (`tests/webinspector.mjs`; corrected M024).
- 2026-10-19 (M011): `fetch()` of a `data:` URL whose base64 holds a character outside the alphabet rejects in Chromium 155 and in desktop and iOS 27.0 Safari, and a self-contained Quarto 1.10 render keeps such a hand-written `data-src`. In puppeteer, `Browser.setDownloadBehavior` with `behavior: "allow"` on `browser.target().createCDPSession()` saves a clicked `blob:` link with a `download` name under that name, on `file://` pages too.
- 2026-10-19 (M011): puppeteer-core imported from a script outside the repo fails with ERR_MODULE_NOT_FOUND (ESM ignores NODE_PATH); run a one-off probe from the repo root as `node --input-type=module -e "$(cat probe.mjs)"`.
- 2026-10-19 (M012): Chromium 155 gives an `<object type="application/pdf">` with an `aria-label` the tree role PluginObject and that name, and shows an `aria-description` equal to it as a description; Safari 27.0.1's WebDriver "Get Computed Label" returns that `aria-label` (computed role group). Desktop Safari has no headless mode, so each safaridriver session brings a Safari window to the front; batch `safari_check.mjs` runs.
- 2026-10-19 (M010): The first `xcrun simctl openurl` on a simulator that ios_check just booted can fail with "Operation timed out" (NSPOSIXErrorDomain code 60); the same run passes when repeated.
- 2026-10-19 (M014): Chromium 155 and Safari 27 (desktop and iOS 27.0) send no Origin header for a native `<object>` read of a PDF and one for PDF.js's fetch; render_check's own `fetch(o.data)` of a native embed's PDF sends one too, but asks for the whole file. Google Chrome is not installed here; render_check runs with `CHROME_PATH=/Applications/Chromium.app/Contents/MacOS/Chromium`.
- 2026-10-19 (M015): `%` starts a LaTeX comment, so a `%` in an `\includepdf` path needs `\begingroup\catcode`\%=12\relax … \endgroup` on the same line; `\csname @percentchar\endcsname` joins a following letter into one command name. In an `\includepdf` file name, `"` and `,` fail in lualatex, pdflatex, and xelatex, and `)` fails in xelatex only.
- 2026-10-19 (M016): Quarto's RevealJS 5 in the iOS 27.0 iPhone simulator uses its scrolled view (`Reveal.isScrollView()` true; not on the iPad): the current slide follows the scroll, `Reveal.slide()` to the last slide left the one before it current, and scrolling its content into view made it current. A walk over `Reveal.getSlides()` skips `data-visibility="uncounted"` slides. A check of the shown slide reads `Reveal.getCurrentSlide()`.
- 2026-10-19 (M014): To compare the v1.2.4 viewer on one page without a re-render, copy `git show main:_extensions/embedpdf/embedpdf-viewer.js` over that page's `docs/<page>_files/libs/quarto-contrib/embedpdf-<version>/embedpdf-viewer.js`, run the check, and copy the new file back (the server sends `no-store`). In zsh a flag list in a variable needs `${=var}` to split into words.
- 2026-10-19 (M019): LuaLaTeX embeds each font subset once per PDF, so 14 pages rendered in one run came to 25,999 bytes; rendering each page in its own run and joining them with `pdfunite` repeats the fonts per page (about 9.5 KB each) and gave 142,962 bytes. `quarto render <file>.md --output-dir <dir>` refuses a file outside the project's render list; `quarto pandoc <file>.md --pdf-engine=lualatex -o <out>.pdf` builds it.
- 2026-10-20 (M020): An element screenshot of a native `<object>` PDF shows the browser's viewer in headless Chromium 155 and Firefox 158 (puppeteer-core) and in desktop Safari 27.0.1 (safaridriver). Firefox's viewer reopens a PDF at the page last shown in that profile unless `pdfjs.viewOnLoad` is 1. Two equal screenshots 500 ms apart can still be the viewer before it drew the PDF.
- 2026-10-20 (M021): A PDF `<iframe>` follows the server's answer: a PDF sent as `application/octet-stream` or with `Content-Disposition: attachment` shows nothing and downloads (Firefox 158, Safari 27.0.1), where `<object type="application/pdf">` shows it. A safaridriver probe of it saves the file in `~/Downloads`; use headless Chromium. A cross-origin fetch cannot read `Content-Disposition`, so a missing and a hidden header look alike.
- 2026-10-20 (M022): Quarto's RevealJS 5 deck (`viewDistance` 3) hides a slide (`display:none`) 3 or more slides from the current one, so an embed there has no box at load. A native PDF `<iframe>` loaded with no box opened at page 1 in Chromium 155 and shrank in desktop Safari 27.0.1 once shown. Reveal's scale is window size x 0.9 / deck size, so no whole-pixel window gives exactly 1; `Reveal.configure({ minScale: 1, maxScale: 1 })` does.
- 2026-10-20 (M022): In headless Chromium 155, each native PDF viewer is a target of type "other" at `chrome-extension://mhjfbmdgcfjbbpaeojofohoefgiehjai/index.html`, with its save button `#save` in the `pdf-viewer` > `viewer-toolbar` > `viewer-download-controls` shadow roots (`Runtime.evaluate` on that target). CDP `Browser.setDownloadBehavior` with `eventsEnabled: true` reports `Browser.downloadWillBegin` and its `suggestedFilename`.
- 2026-10-20 (M023): Desktop Safari 27.0.1's PDF control bar (zoom, open in Preview, download) shows only while the pointer is over the embed, at a height set by the embed's size, and fades once the pointer stops; WebDriver element screenshots miss it (window screenshots show it). A locked screen (`lsappinfo front` names loginwindow) shows no bar. After a burst of saves Safari saved nothing for 2 to 3 minutes, with no error the page sees.
- 2026-10-20 (M023): Firefox 158's embedded PDF viewer saved no file under puppeteer-core (button, menu, Cmd+S; BiDi or prefs; headless or windowed), where an `<a download>` of the same `blob:` saved at once; `PDFViewerApplication._docFilename` in its frame (`page.frames()`) gives the name it would save. Chromium 155's viewer names a save by the address's last path segment (fragment and `File` name ignored), and `download.pdf` for `data:`.
- 2026-10-20 (M025): A full run of the CLAUDE.md check lines (138 with prose variants) took 28 to 35 minutes. The desktop Safari lines take over Safari (windows in front, the pointer moves), and a screen locked mid-run made the save line fail. The user objected to runs while their own Safari windows were open, and safaridriver then failed ("session timed out while connecting to a Safari instance"). Ask before running the desktop Safari lines.
- 2026-10-20 (M024): Over an iOS 27.0 simulator's Web Inspector socket, Safari's page answers only through `Target.sendMessageToTarget` to the page target that `Target.targetCreated` names after `_rpc_forwardSocketSetup:`. A page opened with `simctl openurl` is listed before it loads, so a check waits for `document.readyState` "complete". Xcode 27.1 ships no Simulator.app; its simulator window is `Contents/Applications/DeviceHub.app`.
- 2026-10-20 (M026): Quarto 1.10.19's `quarto add jmgirard/embedpdf` downloads `archive/refs/heads/main`, not the latest GitHub release (`githubLatestUrlProvider` in `quarto.js`), so a tag or release changes only the releases page and the README badge. `gh api .../releases/tags/<tag> --jq .body` prints the body plus one newline, so a byte compare with its notes file adds one.
