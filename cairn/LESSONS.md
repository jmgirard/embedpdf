# Lessons

Durable repo lessons — build quirks, testing tricks, gotchas worth
remembering next time — captured at milestone end and surfaced at plan time.
Not status, not decisions: a lesson is a reusable "how this repo actually
behaves" note. Cross-cutting *choices* still go to `DECISIONS.md`.

One line per lesson: `- YYYY-MM-DD (M<NNN>): <lesson>`. Two caps: 50 lines
and 20,000 bytes; over either, retire or prune before adding. Corrected in
place when proven false (never append a correction).

- 2026-10-18 (M001): `xcodebuild -downloadPlatform iOS` with Xcode 27.1 installs two runtimes: iOS 27.1 supports only the "iPhone Duo" device type, and the standard iPhones and every iPad need the iOS 27.0 runtime. Check `xcrun simctl list runtimes -j` (supportedDeviceTypes) before `simctl create`.
- 2026-10-18 (M002): With `embed-resources: true`, Quarto 1.10 inlines module scripts as `data:` URLs (its tabsets scripts too), a script of unknown type as its text, and each `data-src` as a `data:` URL, and adds `role="img"` to elements whose `data-src` it inlined. It leaves `<a href>` targets at the file.
- 2026-10-18 (M003): Safari reports a CORS-blocked PDF.js fetch only as "UnknownErrorException: Load failed" (a CORS block and a module-import failure differ only in the message), and a 404 as "ResponseException: Unexpected server response (404)" (corrected M007), while Chromium logs UnknownErrorException for a CORS block and ResponseException for a 404. A check of a failure's cause reads the viewer's own "embedpdf: failed to render <data-src>" line, not any console CORS line: render_check's native `<object>` fetch logs CORS errors of its own. The viewer names the PDF by its `data-src` as written (`sample.pdf`, not the absolute URL) and logs one line per failed embed, so embeds sharing a PDF give as many lines.
- 2026-10-18 (M004): Puppeteer's `page.accessibility.snapshot({ root })` with the default `interestingOnly: true` returns a labeled group's child text node, not the group, so a role or name check needs `interestingOnly: false`. In Chromium a `<canvas>` without `aria-hidden` shows in that tree as role `none`.
- 2026-10-18 (M004): Quarto's self-contained render passes the inlined viewer through esbuild, which drops comments, so a comment-only change to `embedpdf-viewer.js` changes the docs/ library copies but not the self-contained pages.
- 2026-10-18 (M005): Chromium exposes a `title` equal to an element's `aria-label` as its accessible description too (puppeteer snapshot `description`), so the name is read twice. A control named by `title` alone, with its glyph in an `aria-hidden` span, gets that name and no description.
- 2026-10-18 (M005): PDF.js 6.1.200 `getTextContent()` adds `" "` items for gaps between pieces of text and sets `hasEOL` at line changes, so joining `item.str` values already spaces positioned words and columns. A spacing fix needs a PDF that shows the defect first. The vendored browser build does not run in Node, so probe it in Chromium with puppeteer.
- 2026-10-18 (M006): On macOS a Node server listening on 127.0.0.1:N starts with no error while another process listens on `0.0.0.0:N` or `[::]:N` (SO_REUSEADDR), so an EADDRINUSE check sees only a holder on 127.0.0.1 itself. PDF.js 6.1.200 asks for byte ranges only when Content-Length is above 2 × 65536 bytes and the server sends `Accept-Ranges: bytes` (`validateRangeRequestCapabilities` in `pdfjs/pdf.min.mjs`).
- 2026-10-18 (M002): A PDF.js embed on a RevealJS slide that is not shown renders nothing (its pages have width 0), so a render check must go to each slide with `Reveal.slide()` before it measures ink; scrolling the window does not move slides.
- 2026-10-19 (M009): In Chromium's accessibility tree (puppeteer snapshot, `interestingOnly: false`), text with `opacity: 0` stays readable, while `content-visibility: hidden` on the element or an ancestor and `inert` on the element or an ancestor remove it. An inert ancestor leaves the element's own `inert` property false, so a check reads `closest("[inert]")` or walks the ancestors.
- 2026-10-18 (M008): Quarto 1.10 copies a resource and inlines a PDF whose path holds a bare `%` (`files/100%.pdf`), with a "WARN: Invalid URI" line, and keeps the `<a download>` href as written; GitHub Pages and `serveDocs` answer HTTP 400 to a bare `%` path, so such an embed works only on a self-contained page. A `div.embedpdf` with no `data-src` never hydrates, which makes a quick probe of a check's hydration timeout.
- 2026-10-19 (M010): safaridriver (Safari 27.0.1) refuses a session until "Allow remote automation" is on (Safari Settings > Developer, or `safaridriver --enable` with an admin password). Its "Get Computed Label" returns "" for a plain `span`, so a check reads text by giving the element a name-from-content role such as `heading` for the read. In the iOS 27.0 simulators a `safari:useSimulator` session fails with "Could not find any session hosts that match the requested capabilities", and Safari has no `Element.prototype.computedName`.
- 2026-10-19 (M010): The first `xcrun simctl openurl` on a simulator that ios_check just booted can fail with "Operation timed out" (NSPOSIXErrorDomain code 60); the same run passes when repeated.
